# 弈象棋局文件第 1 版

“导出本局”和收藏中的导出使用同一种 UTF-8 JSON 文件。它用于手动转移一盘棋；课程进度、错题、首盘记录和浏览器设置不随文件转移。

## 示例

以下文件记载红方挺起边兵后的棋局，并附有第 1 着笔记：

```json
{
  "format": "yixiang-game",
  "version": 1,
  "title": "我的第一盘棋",
  "startMoves": [],
  "moves": [
    { "from": { "x": 0, "y": 6 }, "to": { "x": 0, "y": 5 } }
  ],
  "ending": null,
  "notes": { "1": "行棋前先观察对方的威胁。" }
}
```

## 字段与坐标

| 字段 | 含义 |
| --- | --- |
| `format`、`version` | 固定为 `"yixiang-game"` 和数字 `1` |
| `title` | 去除首尾空白后为 1 至 40 字的名称 |
| `startMoves` | 从标准开局走到本局起始位置的实际着法；标准开局为空数组 |
| `moves` | 从该起始位置继续走出的本局着法 |
| `ending` | 没有人工结束声明时为 `null`；认输为 `{"reason":"resignation","side":"red"}` 或 `black`；议和为 `{"reason":"agreement"}` |
| `notes` | 可省略；键为本局第几着，从 `"1"` 起，值为 1 至 500 字的非空笔记 |

坐标以红方在下的棋盘为准：左上交叉点是 `(0, 0)`，右下是 `(8, 9)`。`x`、`y` 均为整数。翻转观看方向不改变文件坐标。每一着只含 `from`、`to`，每个位置只含 `x`、`y`；其它字段不予接受。

`startMoves` 不计入本局笔记索引。两段合计须为 1 至 600 着。已有棋路前缀但本局尚未落子时，可以有非空 `startMoves` 和空 `moves`。

## 校验与结局

导入从标准开局逐着重放两段着法，重建棋盘、轮到谁走、中文记谱、吃子、将军、重复提示及终局。非法着法、终局后的续走、无法重放的起始局面和不支持的版本均会拒绝。将死、困毙与自然限着由规则计算，无需在 `ending` 中填写。

认输的 `side` 是认输方。认输与议和是文件记载的人工声明，不能覆盖已由规则产生的终局，也不代表软件验证了双方现实中的约定。规则仍沿用游戏现有边界：重复局面提示，复杂循环棋例不做赛事级自动裁决。

文件不接受棋盘快照、胜方、着法评语、账号、设备路径、学习奖励或外部网址字段。名称和笔记作为普通文本展示。

## 笔记、容量与转移

- 导出默认不含笔记，主动勾选后才附加已保存笔记。编辑框中尚未保存的草稿不会自动加入。
- 每个导入或导出文件最多 512 KiB，按 UTF-8 字节计算。带笔记超过上限时，可以取消包含笔记再导出。
- 本机收藏最多 20 盘，规范化 JSON 总量最多 2 MiB；本机收藏可以保留完整笔记，因此与单文件上限分开计算。
- 浏览器存储仍可能提前写入失败。页面出现未保存提示时，内存中的内容尚不能保证刷新后恢复。
- 导入先预览，再明确加入收藏；每次加入均生成新的本机标识。同一文件可以存为另一份副本。
- 收藏和导入预览独立于当前对局。选择“从末着继续练习”后才替换当前对局；原收藏保持不变。续练不授予首盘或独立首盘记录。

在另一台设备上打开游戏并选择导出的文件，即可手动转移棋局。收藏本身仍保存在当前浏览器中；清除网站数据会删除本机收藏。复制棋谱产生的文字、通用 PGN/FEN 及任意摆棋文件不属于本格式。
